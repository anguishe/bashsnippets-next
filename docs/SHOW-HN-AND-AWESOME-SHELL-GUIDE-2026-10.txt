FIRST COMMENT 2
--------------------------------------------------------------------------------
I kept reading ss -tulpn and missing the one row that mattered. For months a docker-proxy sat on 0.0.0.0:3000 on my laptop, publishing a web UI to the whole network, and it was on the first lines of the output every time I looked.

This takes pasted ss, netstat or lsof output and gives each listener a card: who could reach it (loopback only, one interface, or every interface), which process or systemd unit owns it, and flags for the risky cases: a database or the Docker API on a wildcard address, a published container port, a dev server on the network, a full accept queue. Each card has the next command to run.

Privacy first, because it is the obvious question: parsing happens in the browser and nothing is uploaded. Redaction is on by default and masks non-loopback addresses on screen and in the share link, so a link can be posted without leaking your IPs.

It can't see your firewall, security groups or NAT, and it says so. It tells you what could be reachable, not what is. Bug reports with sample output are welcome.
--------------------------------------------------------------------------------
  (The docker-proxy story is the real opener of /guides/open-ports-linux,
  run on this laptop. The ufw bypass is in the tool as documented Docker
  behaviour, so don't claim you reproduced it unless you do it first.)
